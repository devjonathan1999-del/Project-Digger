# Industry v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer la première boucle jouable de gestion de ressources persistante approuvée par Jonathan.

**Architecture:** IndustryGame est un modèle déterministe sans horloge ni UI, IndustrySave persiste son état, IndustrySession réconcilie temps réel et actions. IndustryScreen présente la gestion et MineOverview dessine la coupe du sous-sol.

**Tech Stack:** Godot 4.7.2 stable, GDScript, rendu gl_compatibility, tests headless existants.

**Spec:** `docs/superpowers/specs/2026-09-10-industry-v0.2-design.md`

## Global Constraints

- Godot 4.7.2 stable, GDScript, rendu gl_compatibility ; aucun plugin tiers.
- Interface en français ; le modèle contient toutes les règles de ressources, recettes et progression.
- Trois minerais : iron, coal, copper ; produits : iron_ingot, copper_ingot, cable.
- Extraction automatique, fabrication par lots de 1 à 10, deux installations indépendantes furnace/workshop.
- Progression persistante, aucune remise à zéro de campagne, aucune pénalité liée à l'absence.
- Fichier industriel dédié user://industry_v1.json ; ne jamais modifier la sauvegarde terrain v0.1.
- Tous les anciens tests restent verts. Pas de dépendance au cache .godot pour importer les nouvelles classes.
- Les tests ciblés sont exécutés dans des chemins dédiés ; ne jamais utiliser la sauvegarde du joueur.
- Pas de push/merge externe par les sous-agents ; chaque intervenant ne commit que ses fichiers.

## Interfaces communes

`IndustryCatalog` est un RefCounted à constantes dictionnaires : RESOURCES (id -> {label, raw}), MINES (raw id -> {label, base_rate}), RECIPES (id -> {label, facility, inputs: Dictionary, output: String, seconds: float}), MAX_MINE_LEVEL=10, MAX_DRILL_LEVEL=5.

`IndustryGame` est un RefCounted avec `resources: Dictionary`, `mine_levels: Dictionary`, `drill_level: int`, `depth: int`, `jobs: Dictionary`. Un travail est indexé par furnace/workshop/drill et contient `remaining: float`, `duration: float`, plus `recipe: String` et `quantity: int` pour fabrication, ou `target_depth: int` pour forage. Le travail disparaît à son terme.

API : `advance(seconds: float) -> Dictionary` renvoie `{produced: Dictionary, completed: Array, depth_gained: int}`. `snapshot() -> Dictionary`, `restore(data: Dictionary) -> bool` (sans mutation sur rejet), `can_afford(cost: Dictionary) -> bool`, `mine_rate(id: String) -> float`, `mine_upgrade_cost(id: String) -> Dictionary`, `drill_upgrade_cost() -> Dictionary`, `batch_block_reason(recipe: String, quantity: int) -> String`, `excavation_block_reason() -> String`, `excavation_duration() -> float`, `start_batch(recipe: String, quantity: int) -> bool`, `upgrade_mine(id: String) -> bool`, `upgrade_drill() -> bool`, `start_excavation() -> bool`. Raisons vides = action valide. Les stocks sont des nombres réels ; les quantités/couts de recettes entiers.

`IndustrySave.save_game(path: String, game: IndustryGame, saved_at_unix: float) -> bool`. `load_game(path: String, now_unix: float) -> Dictionary` renvoie `{game: IndustryGame, saved_at_unix: float, offline_seconds: float, offline_report: Dictionary, error: String}`. Si absent : nouvelle partie et erreur vide ; si invalide : nouvelle partie provisoire, erreur non vide, fichier préservé. `saved_at_unix` retourné vaut max(instant sauvegardé, maintenant) après avancement.

`IndustrySession extends Node` : `game: IndustryGame`, `save_path: String` initialement IndustrySave.DEFAULT_PATH, `save_error: String`, `offline_seconds: float`, `offline_report: Dictionary`, `save_blocked: bool`. Signaux `changed`, `notice_changed`. Méthodes `initialize(now_unix: float) -> void`, `advance_to(now_unix: float) -> void`, `persist() -> bool`, `start_batch(recipe: String, quantity: int) -> bool`, `upgrade_mine(id: String) -> bool`, `upgrade_drill() -> bool`, `start_excavation() -> bool`. La session initialise automatiquement dans _ready sauf si déjà initialisée explicitement pour un test. `last_seen_unix: float` est l'instant logique validé. Les actions publiques utilisent advance_to(Time.get_unix_time_from_system()) avant leur exécution. `advance_to` est injectable pour tests, ne recule pas l'instant logique. _process emploie l'horloge pour les gains, delta uniquement pour la fréquence UI/sauvegarde.

### Task 1: Modèle économique et progression

**Files:** Create `src/industry/industry_catalog.gd`, `src/industry/industry_game.gd`, `tests/test_industry_game.gd`; modify `tests/test_runner.gd` uniquement pour ajouter cette suite.

Valeurs exactes : stocks initiaux iron=12, coal=8, copper=8, produits=0. Niveaux mines=1, foreuse=1, profondeur=0. Débits base iron=0.20, coal=0.12, copper=0.10 par seconde ; débit effectif = base × niveau × (1+0.15×floor(depth/30)). Cout amélioration mine niveau L : iron=8×L², coal=4×L². Cout foreuse niveau L : iron_ingot=2×L, cable=L. Excavation +10m, durée (30+depth×0.5)/drill_level ; niveau requis min(5,1+floor((depth+10)/30)). Niveaux maxi mine10 foreuse5.

Recettes : iron_ingot (label Lingot de fer, furnace, inputs iron4+coal1, output iron_ingot, 20s) ; copper_ingot (Lingot de cuivre, furnace, copper3+coal1, output copper_ingot,25s) ; cable (Câble, workshop, copper_ingot2+iron_ingot1, output cable,40s). Sortie quantity à la fin du lot. Les couts sont prélevés une seule fois au lancement ; nombre d'unités 1..10.
