# Project Digger — Visual v0.4 Design

## Statut

Design validé conceptuellement à partir du mockup retenu et de la capture réelle v0.3. Cette v0.4 est une refonte de présentation de la vue Mine, sans changement de règles économiques.

## Objectif

Faire passer l’écran Mine de « prototype fonctionnel / interface de gestion » à « scène principale de jeu ».

La mine doit devenir le centre visuel de l’expérience : le joueur doit d’abord regarder un monde souterrain vivant, puis utiliser l’interface pour agir dessus. Les systèmes v0.3 restent la source de vérité et ne sont pas modifiés.

## Problèmes observés en v0.3

- Le HUD ressources consomme trop de hauteur avec sept grosses cartes.
- Le panneau « Commandes foreuse » est permanent et occupe une grande partie de l’écran.
- La mine représente seulement environ la moitié de la zone utile.
- Les cibles Fer / Charbon / Cuivre / Découverte / Foreuse ressemblent à des boutons de debug plutôt qu’à des éléments du décor.
- La surface est représentée par des rectangles fonctionnels, pas par une base minière crédible.
- Les couches géologiques sont lisibles mais trop plates.
- La direction rétro-futuriste industrielle validée n’est pas encore visible : acier sombre, cuivre, rivets, tuyaux, lampes ambre, machinerie massive.
- Les accents sci-fi profonds existent déjà mais sont encore trop abstraits.

## Non-objectifs

La v0.4 ne modifie pas :

- les coûts ;
- les temps ;
- les rendements ;
- les formules de profondeur ;
- les événements ;
- le schéma de sauvegarde ;
- la migration v1 → v2 ;
- les règles de Centre, capacité ou technologie ;
- les API publiques de `IndustryGame` et `IndustrySession`.

Aucune nouvelle ressource de gameplay n’est ajoutée.

## Direction artistique

### Identité

Direction retenue : **75 % rétro-futuriste industriel / 25 % sci-fi industrielle sobre**.

Le monde utilise principalement :

- acier sombre ;
- cuivre / laiton patiné ;
- rivets et plaques mécaniques ;
- tuyaux, rails, poutrelles et plateformes ;
- éclairage ambre chaud ;
- gros volumes mécaniques lisibles.

Les profondeurs ajoutent progressivement :

- lumière cyan / turquoise ;
- capteurs avancés ;
- cristaux lumineux ;
- anomalies et halos ;
- structures plus propres et plus mystérieuses.

Le jeu ne doit pas devenir steampunk caricatural : pas de multiplication décorative de rouages, pas de fantasy victorienne.

## Approches envisagées

### A — Tout dessiné en code

Étendre `MineWorld._draw()` et les `Control` existants pour tout représenter en formes primitives.

Avantages : rapide, cohérent, facile à tester et responsive.

Inconvénients : risque de rester trop abstrait et « prototype ».

### B — Asset pack complet

Créer une bibliothèque de sprites dédiée pour chaque bâtiment, convoyeur, machine, galerie et biome.

Avantages : potentiel visuel maximal.

Inconvénients : trop lourd pour cette étape, beaucoup d’assets à produire, maintenir et adapter aux tailles d’écran.

### C — Hybride modulaire — retenue

Conserver le rendu procédural pour la géologie, les rails, câbles, tuyaux, lumières et états actifs ; construire quelques modules illustrés réutilisables directement en Godot avec des contrôles composés et formes détaillées : base de surface, ascenseur, convoyeur, foreuse, mine, site profond, cristaux.

Cette approche conserve la flexibilité actuelle tout en donnant une vraie identité visuelle.

## Architecture UI v0.4

### 1. HUD supérieur compact

Le bandeau supérieur devient une seule ligne compacte.

Contenu :

- petit titre `DIGGER` à gauche ;
- Fer ;
- Cuivre ;
- Charbon ;
- Lingot fer ;
- Lingot cuivre ;
- Câble ;
- Cristal ;
- capacité si pertinente ;
- profondeur à droite.

Les ressources ne sont plus des cartes hautes mais des chips/badges de 30–38 px de hauteur.

À 1280×800, le HUD complet doit rester sous ~70 px de hauteur.

### 2. Vue Mine dominante

Sur l’onglet Mine :

- suppression du titre `MINE` et du paragraphe pédagogique permanents ;
- raccourcis Surface / Foreuse / paliers intégrés comme petite barre flottante sur le monde ;
- la mine occupe environ 70–75 % de la zone utile ;
- aucune colonne latérale permanente ne réserve 280 px.

Le monde doit rester le premier élément lu visuellement.

### 3. Panneau contextuel flottant

`SitePanel` reste la source des actions contextuelles, mais il n’occupe plus une colonne fixe.

Desktop :

- panneau flottant à droite du monde ;
- largeur cible 300–340 px ;
- affiché uniquement après sélection.

Écran étroit :

- panneau en bottom-sheet flottante ;
- largeur quasi complète ;
- fermeture explicite ;
- ne redimensionne pas durablement la mine.

La foreuse utilise ce panneau comme les autres éléments. Le bloc permanent `COMMANDES FOREUSE` disparaît.

### 4. Navigation basse

La barre `Mine / Industrie / Centre / Technologie` reste.

Objectif : hauteur 42–50 px, plus fine que la v0.3.

L’onglet actif est clairement visible par contraste et accent cuivre/cyan discret.

### 5. Événements et retour hors ligne

`Filon instable` et le bilan hors ligne ne doivent plus repousser la mine verticalement.

Ils deviennent des cartes flottantes temporaires dans la partie supérieure du monde, avec priorité visuelle mais sans bloquer la caméra.

## MineWorld v0.4

### Composition générale

Le puits central actuel est conservé comme repère principal.

Le monde se compose de :

1. surface industrielle ;
2. puits central ;
3. galeries latérales ;
4. sites d’extraction ;
5. foreuse au front de taille ;
6. poches et découvertes latérales ;
7. couches géologiques évolutives ;
8. éléments de vie et éclairage.

### Surface évolutive

La surface utilise `center_level` uniquement comme donnée visuelle existante.

Proposition :

- Centre 1 : petit bâtiment + chevalement ;
- Centre 2 : silo / stockage ;
- Centre 3 : atelier et réseau de tuyaux ;
- Centre 4 : grue / passerelles ;
- Centre 5 : capteurs et module industriel avancé ;
- Centre 6 : antenne / instrumentation cyan discrète.

Aucun bonus supplémentaire n’est créé.

### Galeries

Les galeries ne sont plus de simples lignes horizontales.

Chaque niveau visible doit suggérer :

- une cavité creusée ;
- rails ou convoyeur ;
- poutrelles de soutien ;
- câbles / tuyaux ;
- une ou deux lampes ambre ;
- un petit volume de machine ou de stockage.

### Mines Fer / Charbon / Cuivre

Les gros boutons texte sont remplacés par :

- un module machine/extraction visible ;
- une petite étiquette courte ancrée au décor ;
- une zone de clic transparente suffisamment large pour rester utilisable.

L’activité existante est communiquée visuellement : mouvement léger, bande transporteuse, particules abstraites ou lampe active.

### Foreuse

La foreuse devient un élément fort du monde :

- tête de forage orientée vers le bas ;
- structure acier/cuivre ;
- éclairage ambre ;
- animation mécanique lors d’un chantier ;
- timer attaché directement à la machine.

Ses boutons d’action existent uniquement dans `SitePanel`.

### Découvertes

État non exploré :

- pas de gros bouton `Forte signature minérale` ;
- fissure, halo, minerai visible ou signal lumineux ;
- petite étiquette `Signal minéral`, `Anomalie`, `Structure` si nécessaire.

État exploré :

- la cavité s’ouvre visuellement ;
- site permanent : installation construite reste visible ;
- site épuisable : cavité reste comme trace historique mais devient inactive.

### Profondeurs

0–30 m : terre/roche brun-gris, installation rudimentaire, lumière chaude.

30–60 m : roche acier/bleu-gris, veines métalliques, davantage de rails et structures.

60–90 m : roche dense sombre, installations plus massives.

90–120 m : cristaux cyan, instrumentation avancée.

120–150 m : cavités plus larges, structures anciennes/abandonnées, contraste ambre-cyan.

150 m+ : zone plus spectaculaire et mystérieuse, sans ajouter de gameplay dans cette v0.4.

## Interaction et caméra

La logique existante reste :

- drag vertical ;
- zoom limité ;
- raccourcis Surface / Foreuse / paliers ;
- sélection d’un élément ;
- action via `SitePanel`.

Les zones de clic restent des `Control`/`Button` invisibles ou très sobres, afin de préserver l’accessibilité et les tests UI réels.

## Répartition du code

### `industry_screen.gd`

Responsabilités v0.4 :

- shell général ;
- HUD compact ;
- navigation basse ;
- overlays événement/offline ;
- affichage responsive du `SitePanel`.

Il ne dessine pas le monde.

### `mine_world.gd`

Responsabilités :

- caméra / zoom / drag ;
- positions spatiales ;
- interactions ;
- état d’animation ;
- coordination du rendu.

Le fichier doit être allégé si nécessaire en extrayant le rendu statique.

### Nouveau `mine_scene_renderer.gd`

`Control` spécialisé, sans logique économique, chargé de dessiner :

- géologie ;
- surface ;
- galeries ;
- puits ;
- structures et machines ;
- halos / cristaux / éclairages.

Il reçoit un état de présentation simple depuis `MineWorld` mais ne modifie jamais `IndustryGame`.

### `site_panel.gd`

Conserve les actions existantes, mais adapte :

- présentation plus compacte ;
- position flottante ;
- variante desktop / bottom-sheet ;
- état visuel cohérent avec le monde.

### `industry_theme.gd`

Ajoute les styles :

- HUD chips ;
- panneau flottant ;
- navigation active/inactive ;
- cuivre/laiton/acier ;
- ambre lumineux ;
- cyan profond.

## Responsive

### 1280×800

- HUD ≤ ~70 px ;
- nav ≤ ~50 px ;
- monde Mine utilise l’essentiel du centre ;
- panneau contextuel overlay à droite ;
- pas de scroll global nécessaire pour voir la Mine principale.

### 720×1000

- HUD passe sur deux lignes compactes au maximum ;
- Mine plein écran central ;
- panneau contextuel en bottom-sheet ;
- navigation reste visible en bas ;
- aucun débordement horizontal.

## Critères d’acceptation visuels

1. À 1280×800, `MineWorld` occupe au moins 70 % de la largeur utile quand aucun panneau contextuel n’est ouvert.
2. Le panneau foreuse permanent n’existe plus.
3. `ContextPanel` est caché par défaut et n’affecte pas la largeur du monde lorsqu’il est fermé.
4. Les ressources tiennent dans un HUD compact, sans cartes de ~70 px de haut.
5. Les raccourcis de profondeur sont intégrés au monde et non dans un bloc vertical dédié.
6. Fer / Charbon / Cuivre ne sont plus représentés par de gros boutons opaques.
7. La surface contient au moins quatre éléments industriels lisibles à Centre 3+.
8. Les galeries visibles contiennent structure, éclairage et transport.
9. La foreuse est identifiable sans texte permanent.
10. Les profondeurs 90 m+ utilisent les accents cyan/turquoise de façon nettement plus forte que les couches superficielles.
11. Les actions contextuelles v0.3 continuent de fonctionner avec de vrais clics.
12. Les suites v0.1/v0.2/v0.3 restent vertes.
13. Les captures CI wide/narrow sont conservées pour inspection.

## Tests

Les tests de gameplay existants doivent rester inchangés.

Tests UI à ajouter/adapter :

- hauteur du HUD ;
- hauteur de navigation ;
- absence du panneau foreuse permanent ;
- `ContextPanel` caché au démarrage ;
- proportions du monde à 1280×800 ;
- passage du panneau en bottom-sheet à 720×1000 ;
- clic mine / découverte / foreuse / site ;
- timer forage/exploration toujours visible dans le monde ;
- éléments de surface selon `center_level` ;
- changement visuel profond sans modification d’état économique.

Les captures CI restent la validation finale de rendu.

## Définition de terminé

La v0.4 est terminée quand :

- l’écran Mine ne ressemble plus à une grille de panneaux ;
- la mine est clairement le héros visuel ;
- les commandes sont contextuelles ;
- l’identité rétro-futuriste industrielle est visible dès la surface ;
- la touche sci-fi augmente avec la profondeur ;
- aucune règle v0.3 n’a changé ;
- toutes les suites automatiques et UI passent sur Godot 4.7.2.
